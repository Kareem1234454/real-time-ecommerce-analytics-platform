# 1. Introduction

The dashboard layer provides real-time visibility into business operations and system health.

It consumes processed datasets generated by Apache Flink and Apache Spark and presents actionable insights to different user groups.

---

# 2. Dashboard Objectives

The dashboard platform should:

* Display real-time business metrics.
* Track operational health.
* Monitor customer behavior.
* Detect abnormal business activity.
* Support executive decision-making.
* Provide historical trend analysis.

---

# 3. User Roles

Different users require different views.

| Role                | Primary Focus        |
| ------------------- | -------------------- |
| Executive           | Business performance |
| Sales Manager       | Revenue and orders   |
| Marketing Analyst   | Customer behavior    |
| Operations Engineer | Platform health      |
| Fraud Analyst       | Suspicious activity  |
| Data Engineer       | Pipeline monitoring  |

Each role accesses only the dashboards relevant to its responsibilities.

# 12. KPI Catalog

| KPI                  | Description                    | Source            |
| -------------------- | ------------------------------ | ----------------- |
| Revenue              | Total sales amount             | Orders            |
| Active Users         | Current active sessions        | Sessions          |
| Conversion Rate      | Orders / Sessions              | Orders + Sessions |
| AOV                  | Revenue / Orders               | Orders            |
| CLV                  | Total customer revenue         | Orders            |
| Cart Abandonment     | Abandoned carts / Carts        | Cart Events       |
| Payment Success Rate | Successful payments / Attempts | Payments          |

Each KPI should include its calculation logic in the implementation documentation.

---

# 13. Refresh Strategy

Recommended refresh intervals:

| Dashboard          | Refresh Interval |
| ------------------ | ---------------- |
| Executive          | 1 minute         |
| Sales              | 30 seconds       |
| Customer Analytics | 30 seconds       |
| Product Analytics  | 30 seconds       |
| Fraud Monitoring   | 10 seconds       |
| Operations         | 5 seconds        |
| System Monitoring  | 5 seconds        |

Refresh rates should balance freshness with infrastructure load.

---

# 14. Dashboard Security

Access should be controlled using role-based permissions.

Examples:

* Executives cannot modify infrastructure settings.
* Operations engineers cannot access customer personal information.
* Fraud analysts can view only fraud-related datasets.

Sensitive information should be masked where appropriate.
